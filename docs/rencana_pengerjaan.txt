GAMBARAN BESAR PROYEK

Proyek ini adalah aplikasi untuk membantu proses pemeriksaan fasilitas ARFF (Airport Rescue and Fire Fighting) di Yogyakarta International Airport (YIA).

Tujuan utama aplikasi:
- Mempermudah petugas dalam melakukan pemeriksaan equipment di lapangan.
- Menggunakan QR Code sebagai identitas setiap equipment agar proses pemeriksaan lebih cepat dan mengurangi kesalahan input lokasi/data.
- Mencatat hasil pemeriksaan secara terstruktur.
- Mengurangi kemungkinan manipulasi atau ketidaksesuaian data pemeriksaan.
- Mempermudah admin dalam memantau data equipment dan hasil pemeriksaan.
- Menyediakan data yang nantinya dapat digunakan untuk rekap atau pembuatan laporan.

CAKUPAN UTAMA

Fokus pemeriksaan saat ini adalah equipment ARFF yang berkaitan dengan kebutuhan proyek, terutama hydrant dan APAR. Sprinkler tidak termasuk dalam cakupan versi ini.

Area pemeriksaan dibagi menjadi beberapa zona, yaitu Zona A, B, C, dan D.

APLIKASI TERDIRI DARI DUA SISI UTAMA

1. Sisi User / Petugas
Petugas menggunakan aplikasi untuk melakukan pemeriksaan di lapangan.
Gambaran alurnya:
- Login.
- Melakukan scan QR Code pada equipment.
- Sistem mengenali equipment yang diperiksa.
- Menampilkan informasi equipment yang relevan.
- Petugas mengisi hasil pemeriksaan sesuai kebutuhan.
- Data pemeriksaan disimpan ke sistem.

2. Sisi Admin
Admin digunakan untuk mengelola dan memantau sistem.
Gambaran fungsinya:
- Mengelola data equipment.
- Mengelola identitas/QR Code equipment.
- Melihat data hasil pemeriksaan.
- Memantau kondisi atau status pemeriksaan.
- Mengelola data yang diperlukan untuk operasional sistem.
- Menyediakan atau menyiapkan data untuk kebutuhan laporan.

GAMBARAN TEKNOLOGI

Teknologi yang telah direncanakan:
- Frontend: React + Vite.
- Styling: Tailwind CSS.
- Backend: Node.js + Express.
- ORM/database access: Sequelize.
- Database: MySQL.
- Nama database yang digunakan: arff2.
- Authentication: JWT dan mekanisme keamanan yang sesuai.
- QR Code: library yang sesuai untuk generate dan scanning QR.
- HTTP communication: API antara frontend dan backend.

Agent tidak harus terpaku pada semua pilihan teknologi di atas. Pilihan tersebut adalah baseline. Jika terdapat alternatif yang lebih tepat untuk kebutuhan proyek, agent dapat mengusulkannya beserta alasan yang jelas sebelum mengubah arah implementasi.

PENGEMBANGAN YANG DIHARAPKAN

Kembangkan proyek secara bertahap, mulai dari fondasi sistem dan alur utama sampai fitur pendukung.

Urutan besarnya dapat berupa:
1. Memahami kebutuhan dan alur bisnis pemeriksaan ARFF.
2. Menentukan desain sistem dan data yang paling sesuai.
3. Menyiapkan backend, database, autentikasi, dan API inti.
4. Menyiapkan frontend untuk alur user/petugas.
5. Menerapkan proses scan QR dan pengambilan data equipment.
6. Menerapkan proses input dan penyimpanan hasil pemeriksaan.
7. Membangun sisi admin untuk pengelolaan dan monitoring.
8. Menambahkan kebutuhan rekap/laporan.
9. Melakukan pengujian alur utama dan memperbaiki masalah usability, keamanan, serta efisiensi.
